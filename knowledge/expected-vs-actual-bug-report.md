# Expected vs Actual: Writing a Useful Bug Report

The most useful bug reports answer two questions clearly: what should have happened, and what actually happened?

## Template
- **Summary:** One line describing the defect
- **Environment:** OS, browser, app version, user role
- **Steps:** Numbered reproduction steps
- **Expected:** Intended behavior
- **Actual:** Observed behavior
- **Evidence:** Screenshot, log snippet, request ID
- **Impact:** Who is blocked and how severely
Separating expected from actual prevents ambiguous reports like "login broken."
