# How I Would Structure a Support Escalation

A good escalation preserves context so engineering does not restart discovery.
- Issue summary and customer impact
- Reproduction steps verified by support
- Environment and scope (one user vs all users)
- Timeline of when it started
- What was already tried
- Logs, IDs, screenshots attached
- Original expected behavior reference
